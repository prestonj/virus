## SysEx and patch format

- **Single Dump = 524 bytes** (from source, Gearmulator `createSingleDump`):
  `F0 00 20 33 01 <dev> 10 <bank> <prog>` + preset bytes `0..255` + checksum +
  preset bytes `256..511` + checksum + `F7`.
  - Each checksum = sum of all bytes from `<dev>` up to (not including) it, `& 0x7F`.
    The second checksum covers the first one too.
  - The redconfetti doc only describes the final checksum. Messages with a wrong
    middle checksum may be rejected or mis-parsed; `virusRender` fixes both.
- **Parameter address** (from source, verified): page `0x70`/`0x71`/`0x6E`/`0x6F`
  index `i` → preset byte `page_order * 128 + i` (page order A, B, 6E, 6F).
  `tools/virus_patch.py` does this from Gearmulator's
  `parameterDescriptions_TI.json` (563 named params; several names alias the
  same byte depending on oscillator/FX mode).
- **redconfetti "Dump offset" column looks 1 lower than Gearmulator's layout**
  (inferred). E.g. Osc 1 Shape = page A idx `0x11` → message byte `0x1A`, doc
  says `0x19`. Use the doc's live-edit page/param pairs, not its byte offsets.
- **Patch name** = preset bytes 240–249 (page `0x71` idx 112–121), ASCII,
  space padded (verified: reads back `-INIT-` and generated names).
- **Send target**: bank `00` + program `0x40` = Single-mode edit buffer.
  Device ID `0x10` = omni.

## Firmware and ROM

- The firmware the emulator needs is `firmware.bin` (8,569,757 bytes) inside
  *Virus TI Software Suite 5.1.7.00.pkg* →
  `Core_components.pkg/Payload/Library/Application Support/Access Music/Virus TI/Common/`.
  Extract with `pkgutil --expand-full`; no install needed. SHA-256
  `8e3daea8…5cd6a`. Kept in `rom/` (git-ignored).
- ROM `-INIT-` is single index **127** (bank 0, prog 127). Factory Oberheim-ish
  singles: `OberBrssMS` (210), `Ld-OB 82 @` (450). Full list: `renders/rom-singles.txt`.
- **ROM singles are stored in an older format (version byte `08`)**; the
  firmware upgrades them to TI format (`0C`) on load, filling TI-only pages with
  defaults (verified via `--dump-out`). `patches/reference/init-ti.syx` is the
  upgraded INIT and is the template for generated patches (generated by
  `build.sh` from the user's firmware, byte-identical each time; not committed). Upgraded patches
  round-trip byte-identical.

## Emulator behaviour

- **Virus renders are bit-identical across runs** (verified), including 12
  renders in parallel — *after* the timing fix below. Any audio change is
  caused by the patch.
- **Timing bug, fixed 2026-10-24**: the first `virusRender` triggered notes when
  the main thread's frame counter crossed a threshold. The DSP thread runs
  ahead of the main thread by a load-dependent amount, so under parallel load
  note-on moved by a few ms. Fit scores before the fix carry that noise (and an
  apparent "saturation helps" result was noise). Now all events are scheduled
  on the DSP thread by ESAI callback count, and recording uses absolute output
  frames. **One ESAI callback = one output frame** (verified: 199,552 callbacks
  vs 199,488 frames read, one block apart). Note onset is a constant 4.6 ms
  after the recording starts (MIDI processing).
- **OB-Xf renders are not repeatable, even with all slop params at 0**
  (verified): it always adds noise to filter cutoff and starts oscillators at
  random phase. Average several renders for targets.
- Both run at 44.1 kHz. `virusRender` and `obxf_render.py` WAVs both start at
  note-on.

## Virus control behaviour (measured unless noted)

### Oscillators
- `Osc1/2 Shape` 64 = sawtooth (INIT default; from param table: 0 = wave,
  64 = saw, 127 = pulse).
- **`Osc2 Detune` is very non-linear** — almost nothing below ~20, then
  ~0.15 cent/step to 80, then steep. Precise table (sine oscillators,
  phase-slope frequency over 6 s; supersedes an earlier FFT table that was
  ±0.5 cent off):

  | value | cents |  | value | cents |  | value | cents |
  |------:|------:|--|------:|------:|--|------:|------:|
  | 0–8   | ≈0    |  | 48    | +4.9  |  | 96    | +16.4 |
  | 16    | +0.5  |  | 64    | +7.3  |  | 112   | +25.1 |
  | 32    | +2.4  |  | 80    | +9.8  |  | 127   | +39.2 |

  Full table: `tools/calibration.json` (`virus_osc2_detune_cents`).
- **Pulse width is linear** (measured from harmonic nulls): `Osc Pulsewidth`
  0 = 50% (square) … 64 = 24.8% … 127 = 1.8% duty, with Shape 127.
  OB-Xf `OscPW` 0 = 50% … 1.0 = 2.5%, also linear. Translate duty → value
  via the two tables.
- **Unison detune** (`Unison Detune`, Twin mode, measured beat): 48 ≈ 5.6 c,
  64 ≈ 8.5 c, 96 ≈ 18 c, 127 ≈ 44 c between the two voices.
  **OB-Xf unison is random**: each voice gets `UnisonDetune` semitones ×
  a random per-voice factor in [−1, 1] (from source, `OscillatorBlock.h`), so
  there's no fixed beat to measure; we match the voices' standard deviation
  to an even Virus spread (approximation, unverified by ear).
  OB-Xf unison voice count = 1 + int(`UnisonVoices` × 32); Virus
  `Unison Mode` 1–15 = 2–16 voices.

### LFO
- **`Lfo1 Rate` (sine) → Hz is exponential** (measured from pitch track):
  48 ≈ 0.53, 64 ≈ 1.08, 72 ≈ 1.56, 80 ≈ 2.2, 96 ≈ 4.9, 112 ≈ 13, 127 ≈ 86 Hz.
  Values below ~40 (< 0.3 Hz) weren't measurable in a 6 s render.
- **`Osc1 Lfo1 Amount` → peak pitch deviation**: ~1.2 cents per step near 64
  (72 ≈ 9.5 c), then exponential (80 ≈ 31 c, 88 ≈ 81 c, 96 ≈ 2 semitones).
- LFO 1 can reach osc pitch, PW, resonance and filter gain on page A, but
  **not cutoff** — LFO → cutoff is LFO 2 (`Cutoff1 Lfo2 Amount`).
- OB-Xf LFO destination switches: 0 = off, 0.5 = +, 1.0 = − (inverted).
  Warmth uses osc 1 + / osc 2 − for an opposed-pitch shimmer.
- `Transpose` (page A 93): 64 = 0, 1 step = 1 semitone (52 → exactly an octave down).

### Filters
- **INIT routing trap**: INIT is `Filter Routing` Serial 4 with
  `Filter Balance` 64, so audio also passes through filter 2. Filter 2's cutoff
  follows filter 1 (`Filter2 Cutoff Link` on) but has **no envelope**
  (`Filter2 Env Amt` 0), so it stays closed while filter 1 sweeps. For a
  single-filter (OB-style) voice set **`Filter Balance` 0** (filter 1 only).
  Verified: brightness-fit error dropped from 0.84 to 0.41 octaves.
- **With Filter 1 in an Analog mode, `Filter Balance` picks which filters you
  hear** (measured, single note, filter 2 unlinked): **0 = filter 1 only,
  64 = filter 1 → filter 2 in series** (identical to filter 1 alone when
  filter 2 is LP at cutoff 127), **127 = filter 2 only** (filter 1 bypassed: HP
  at 127 went near-silent). `Filter Routing` Serial 4 vs Serial 6 made no
  difference with an Analog filter 1 (outputs identical).
- A fixed filter-2 low-pass after the analog filter ("tone control", balance
  64, unlinked) did not help match OB-Xf: the Virus's extra top end changes
  over the note, so a fixed LP either does nothing (cutoff2 ≥ 112) or dulls
  everything.
- `Filter1 Mode` values: 0 LP, 1 HP, 2 BP, 3 BS, 4–7 Analog 1–4 pole.
  Analog 4 pole (7) is the OB-Xa / CEM3320 analogue.
- Analog 4 pole with `Cutoff` 127 is **not fully open**: sustained-chord
  spectral centroid ≈2 kHz vs ≈3.7 kHz for OB-Xf wide open.
- **Virus Analog 4 pole rolls off less steeply than OB-Xf's 4-pole** (measured,
  harmonic spectra of a single note, `renders/obright/harmonics-v2.png`): at
  0.4 s the Virus had ~10 dB more energy at 3–9 kHz with brightness centroid
  matched. Later in the note OB-Xf shows a flat harmonic plateau up to ~1.5 kHz
  then a sharp knee; the Virus slopes off gradually. The user heard this as
  "brighter, not as much OB filter sound". Spectral centroid can't see it —
  use band shapes (`render_lib.band_shape`).
- Analog 4 pole **loses ~8 dB as it closes** to a brass-sustain cutoff, where
  OB-Xf's 4-pole stays roughly level. Brightness can match while loudness
  dips; compensate with `Patch Volume` / saturation (not yet solved).

### Saturation / drive
- **`Saturation Curve` (page A 49) does nothing on the TI** (measured: output
  bit-identical with curve Off vs Soft vs Light at any `Osc Mainvolume`).
  Matches redconfetti's note that the TI Saturation menu only has Osc Volume.
- `Osc Mainvolume` above 64 drives the oscillators harder into the filter:
  96 → centroid +3%, 127 → +9% (and peak level drops ~2 dB).

### Envelopes
- **Virus filter envelope decays at a different shape than OB-Xf's** (measured):
  matching where the sweep ends left the Virus 4–8 semitones brighter for the
  first second. **`Filter Env Sustain Time` below 64 (sustain keeps falling)
  fixes most of it**: 56 cut the 0.3–1 s gap to about +2 semitones.
  `Sustain Time` 64 = flat sustain; lower falls, higher rises.
- Not directly calibrated yet. Fitted values swing a lot between runs for
  short times (amp attack came out 4, 19, 27, 28 across fits), so short
  attack values are poorly constrained by the level-shape metric.
- `Filter Env Release` fitted to ~2 for Obright: the fit only sees the
  release while the target is above −45 dB, so treat very short fitted
  releases with suspicion.

## OB-Xf notes

- Param scaling (from source, `SynthEngine.h`): env times
  `logsc(v, min, 60000 ms, rolloff 900)` with min 4 ms (amp A/D), 8 ms (amp R),
  1 ms (filter env); `Osc2Detune` = `logsc(v, 0.001, 0.6)` semitones;
  `FilterCutoff` = `v * 120` and `FilterEnvAmount` = `v * 140` in semitone-like
  units; cutoff Hz = `440 * 2^(index/12)` after `-45` offset and keytrack.
  `logsc(p,lo,hi,r) = ((exp(p*ln(r+1))-1)/r)*(hi-lo)+lo`.
- **"Obright Original" sounds an octave below the key played** (`Transpose`
  0.249 ≈ −12; OB-Xd import compensation). Matching Virus patch needs
  `Transpose` 52.
- `obxf_render.py --params` dumps 104 params; slop params:
  `EnvelopeSlop`, `FilterSlop`, `LevelSlop`, `PortamentoSlop`.

## Build gotchas

- Gearmulator: build our tool by injecting it with
  `-DCMAKE_PROJECT_gearmulator_INCLUDE=tools/gearmulator-inject.cmake`.
  `cmake_language(DEFER … add_subdirectory)` is not allowed; a plain
  `add_subdirectory` works because link targets resolve at generate time.
  Qualify `virusLib::Device` (ambiguous with `synthLib::Device`).
- OB-Xf: **configure from inside `third_party/obxf`** — its version stamp runs
  `git rev-parse HEAD` in CMake's working directory and fails inside a repo with
  no commits. Python bindings need
  `tools/third_party_patches/obxf-python-matrix-target.patch` (bindings lag an
  engine type change).
- Gearmulator's `parameterDescriptions_TI.json` is loose JSON (trailing commas,
  one single-quoted string); parse only the `parameterdescriptions` array.

- **Fork deadlock in parallel renders (fixed 2026-10-25).** `render_virus`
  runs `virusRender` via `subprocess.run` from a thread pool. On macOS that
  forks, and SciPy's FFT backend (ducc, `pyduccfft`) registers a
  `pthread_atfork` handler that joins its worker threads. One worker sat in a
  condition-variable wait, so `fork()` blocked forever with every render
  thread waiting on children that never started (a translate run hung 13 h at
  0% CPU, intermittently). Fix: `close_fds=False`, so CPython uses
  `posix_spawn`, which runs no atfork handlers. Checked by monkeypatching
  `Popen._posix_spawn`: 100/100 renders spawned that way alongside parallel
  FFTs. Diagnose hangs with `sample <pid>` (macOS).

- **`virusRender --seq <file>`** plays a note list (`<start s> <length s>
  <note> <vel>` per line; note offs sort before note ons at the same frame, so
  repeated notes retrigger). Events fire on the DSP thread at exact frames.
  A one-note list renders bit-identically to `--notes 60 --hold 2`. OB-Xf
  equivalent: `render_obxf_seq` processes audio in chunks between events.
  In the first suite the rhythmic parts' level envelopes lined up within
  10–40 ms between the synths (Clavinet correlation 0.96).

## Fitting method (what works)

1. Fixed voice structure translated by hand from the OB-Xf patch.
2. Amp envelope fitted to the **level envelope** with both filters wide open.
3. Filter fitted to **spectral centroid over time** (octaves, gated to where the
   target is above −45 dB) plus a small level-shape term.
4. Coordinate search, ±step per param rendered in parallel (~1 s per batch).
   A two-stage fit takes ~3 minutes.
5. Always plot (`renders/*/fit.png`) — routing/octave mistakes show up as
   flat or offset curves that no parameter tweak can fix.
6. **Fit the filter over the same examples used for listening** (single note,
   fifth, chord), not one chord. Fitting one low chord passed the metric but
   the user heard every listening example as "a touch brighter"; the error was
   concentrated in the first second.
7. Check brightness per time window (0–0.3 s, 0.3–1 s, 1–2 s), not only the
   overall loss: an average can hide a bright attack.

### Low end / "bassier" (Warmth)
- Same octave on both (single-note peaks at 130.7 Hz). The difference is
  **harmonic balance**: OB-Xf's 2nd/3rd/4th harmonics sit at −1.4/−7.5/−12.2 dB
  re the fundamental, the Virus's at −12.9/−17.7/−20.2 — OB-Xf has a strong
  250–550 Hz body and then falls steeply; the Virus is fundamental-heavy with
  a flatter top. Heard as "OB seems bassier". Third-octave band tables are
  too lumpy on harmonic tones for this; compare harmonic levels instead
  (`tools/eq_fit.py: harmonic_db`).
- OB-Xf Warmth's fundamentals vary run to run (two same-pitch saws with an
  opposed LFO interfere) — always average OB-Xf renders.
- **Virus EQ** (page B, from Gearmulator display tables): gains 0.25 dB/step,
  64 = 0, ±16 dB (`LowEQ Gain` 95, `MidEQ Gain` 92, `HighEQ Gain` 96).
  Low shelf 32–458 Hz (`LowEQ Frequency` 44 = 82 Hz), mid peak 19 Hz–24 kHz
  (54 = 404 Hz, 56 = 451 Hz) with Q 0.28–15.4 (`MidEQ Q-Factor` 20 = 0.51,
  35 ≈ 0.74, 60 ≈ 1.4), high shelf 1.8–24 kHz.
- Free EQ fitting **overfits**: it chose Q 15 (boosting one harmonic) and a
  +12 dB high shelf above the measured band (a loudness-normalisation
  artefact). Cap Q (≤ ~1.4) and leave bands you don't measure alone.
- Best broad fix found: **Mid EQ +8 dB at 404 Hz, Q 0.74** (harmonic-balance
  error 6.77 → 5.24 dB; +12 dB no better). EQ can't fully reproduce OB-Xf's
  filter shape. Sent three variants: body (that mid boost), body+low (plus
  +6 dB low shelf at 82 Hz), sub (Sub Osc triangle, volume 40).

## Cross-mod → Virus FM (measured 2026-10-25)

- **OB-Xf cross-mod is osc 1 → osc 2, exponential.** Code: osc 2 pitch (semitones) +=
  osc1out × OscCrossmod × 48, and osc 1's output swings ±0.5 for saw, triangle and
  pulse alike, so **peak deviation = 24 × OscCrossmod semitones**. A slow-modulator
  trace (osc 1 at 8 Hz, osc 2's pitch tracked) is symmetric in cents: ±24 c per 0.01.
  Osc 1 keeps modulating at Osc1Mix 0.
- **Virus FM is osc 1 → osc 2 too, linear in Hz**: ~2.95 % of the carrier frequency
  per step of Osc2 FM Amount (amount 8: +23.8 % / −23.0 %), the same for any osc 1
  wave in mode **Wave**. Mode **Triangle** measures the same as Wave with a
  triangle osc 1. **Pos Triangle** bends only upward. It is real FM, not phase
  modulation (the trace follows the modulator, not its slope). **It clamps**: above
  amount ~64 the swing stops growing (about −83 % … +135 %).
- **Exponential FM raises the carrier's average pitch; linear FM doesn't.** OB-Xf's
  osc 2 averages 2^(48·xmod·osc1out/12) × its pitch: × sinh(a)/a for saw/triangle
  and × cosh(a) for a 50 % pulse, with a = D·ln2/12 (general pulse:
  pw·2^(k(pw−1)/12) + (1−pw)·2^(k·pw/12), k = 48·xmod). Tubular Bells (pulse,
  ±11.4 st) rises **+3.5 st**: untranslated, every Virus partial was misplaced
  (band error 13.95 dB). `translate.set_osc2_pitch` raises the Virus osc 2 by
  the shift (semitones + Osc2 Detune). Bell partials then land within ~1 %
  (Virus 195/504/1198/1511/1900/2598 Hz vs OB-Xf 189/509/1207/1529/1905/2605).
- Small-depth equivalence: Virus amount ≈ sinh(D·ln2/12) / 0.0295 for OB-Xf peak
  D semitones. Audio-rate tables (calibrated with the shift applied):
  saw/triangle 0.1 → 4, 0.25 → 17, 0.5 → 24, 0.85 → 36; pulse 0.1 → 14,
  0.25 → 20, 0.5 → 28, 0.85 → 32. Before the shift was applied, pulse seemed
  to need 1.5–2× saw; most of that was the Virus imitating the pitch shift.
- Aggregating calibration runs: with only two runs per point, take the
  better-fitting one. A median of two let a 3.9 dB outlier (56) set the pulse
  table to 42 from 0.5 up, and monotonic smoothing carried it on.
- OB-Xf **Tune** is ±1 semitone (`v·2−1`). 5 factory patches use it. The Virus has
  no patch fine tune, so the translator notes it and doesn't map it.
- Measuring audio-rate FM: compare each synth's *change* in harmonic levels from
  its own unmodulated sound. Absolute spectra are dominated by the ~2 dB difference
  between the two triangle waves and gave noisy answers. A saw carrier at 1:1 is a
  bad probe: FM keeps a dense saw-like series on both synths, so the loss is flat.
  Use a triangle carrier, 5 cents detune to average the 1:1 phase.
- Virus FM on a saw carrier works (slow trace shows the same deviation) but
  changes a 1:1 saw spectrum little at audio rate, as on OB-Xf.
- **Triangle oscillators were silently translated as saw** (OB-Xf: neither saw nor
  pulse on = triangle). Now Virus Shape 0 + Wave Select 1. 80 cross-mod patches use
  a triangle osc 1.

## Mixer, ring mod and filter drive (measured 2026-10-26)

`calibrate.py mixer`: triangle oscillators a fifth apart, so osc 1 (f1), osc 2 (f2)
and the ring products (f2 ± f1) are measured separately in one render.
- **OB-Xf mixer**: out = osc1·mix1 + osc2·mix2 + osc1·osc2·ring (+ noise). Osc
  outputs swing ±0.5, so the ring product is small: ring 1.0 sits ~14 dB below a
  full oscillator, ring r ≈ 20·log10(r) − 14 dB. Mix levels are close to linear
  amplitude (0.5 → −5.7 dB, 0.25 → −11.9 dB).
- **Virus Ringmodulator Volume** is a true osc 1 × osc 2 product with its own
  level, unaffected by Osc Balance and Osc Mainvolume: 16 → −45 dB, 32 → −38,
  64 → −29, 127 → −17 (re full-scale; the oscillators sit near −18…−20). Ring 127
  is ~3 dB above an oscillator.
- **Osc Balance is near equal-power**: at 64 osc 1 −19.5 / osc 2 −20.9 dB; equal
  levels at ~72; each side drops steeply only near the far end (osc 1: 96 → −25.5,
  112 → −31.5, 127 → off). The old linear mapping was a few dB off; now by table.
- **Osc Mainvolume** scales the oscillators (64 = full, 40 → −7 dB, 16 → −17 dB,
  0 = off) but not the ring, so Mainvolume 0 + ring gives pure ring mod.
- Mapping (`map_mixer`): balance from the osc 2 − osc 1 dB difference; ring
  volume so the ring sits at OB-Xf's level re the louder osc; if ring 127 is
  not enough, lower Mainvolume. Check with saws and triangles: osc and ring
  levels within ~1–4 dB of OB-Xf.
- **The Virus analog filters saturate hard at Mainvolume 64.** Two saws a fifth
  apart, cutoff open, Analog 2 or 4 Pole: intermodulation at f1+f2 is −14.8 dB
  re osc 1 (LP digital −76 dB; OB-Xf −81 dB at cutoff open, −57 at 0.4). Each dB
  of Mainvolume cut lowers it ~2 dB: 56 → −18.8, 48 → −22.3, 40 → −25.4,
  32 → −28.5, 24 → −31.8, 16 → −36.8, 8 → −43.8. Every translated patch so
  far used Mainvolume 64, so all carry this grit; it may be part of the "OB
  filter character" gap on Obright. It also floors weak ring mod: a ring
  below ~−15 dB re the oscillators is masked by the filter's own intermod.
  Listening test sent: Obright at Mainvolume 64 / 40 / 16
  (`renders/obright_drive_variants.wav`).
- Ring-mod factory patches nearly always combine it with other untranslated
  features (brass: env → pitch; keys: legato). Test patches: Kawari (ring 1.0,
  blocker EnvLegatoMode) and Acidisillification (ring 0.28, LFO 2 waveform).
  Results: Kawari amp 2.77 dB, bands 10.32 dB (ring −14.5 dB → volume 43; also
  triangle cross-mod FM 18). Acidisillification bands 11.62 dB, but a poor test:
  its LFO 2 swings osc 2 ±60 st with a non-sine wave (Virus LFO max ~±32 st),
  and its ring (−25.5 dB) sits under the analog filter's intermod. Demo
  `renders/ring_suite_AB.wav`. **User: "do not match at all"**, but both mix
  ring with features the Virus can't match, so they don't isolate ring mod.
- **Isolated ring test** (`renders/ring_isolated_AB.wav`: bare saws, filter open,
  no fitting; A pure ring a fifth apart, B oscs + ring 0.7, C octave +7 c):
  user **"closer for sure; A misses some high-end sizzle and random movement"**.
  Measured on A: the Virus is 4.6 dB short at 6–12 kHz and 8 dB above 12 kHz
  (its analog filter rolls off even fully open; digital LP recovers about half).

  off in one render), Virus 1.6.

## Arturia Jun-6 V as a reference (2026-10-26)

Hosted headless with Spotify's `pedalboard` (pip, in .venv); helper
`tools/jun6.py`, state codec `tools/juce_state.py`. See docs/VINTAGE_TARGETS.md
for why the Juno.
- **Block size matters**: at pedalboard's default buffer (8192) Jun-6 V plays
  nothing (Mini V4 and Jup-8 V4 too, VST3 and AU). `buffer_size=512` works, on
  any MIDI channel. Licensing was not the problem: it runs headless.
- **The first render after loading a preset is silent**: render once and
  discard, then render for real.
- **Preset files are the plugin's state.** `/Library/Arturia/Presets/Jun-6 V/
  Factory/**` are boost `serialization::archive` text; the VST3 state is JUCE's
  "VC2!" XML whose `<IComponent>` is that same text in JUCE's base64 variant
  ("size.chars", 6 bits/char LSB-first, table ".A–Za–z0–9+"). Loading a preset =
  put the file into IComponent and set `raw_state`. The state's own name header
  then still shows the old name; parameters do change.
- 181 parameters in **display units** (vcf_cutoff_hz, envelope_1_decay_s,
  volume_db, switches by name): far easier than OB-Xf's 0–1 values.
- **Factory presets: 56 "Vintage Factory"** (the original Juno-6 sounds, 11–78)
  + ~150 Arturia ones.
- Not deterministic: `voice_calibration` (Good/…), `chorus_noise`, DCO drift.
  Average renders or switch these off when fitting.
- The default patch is quiet (−27 dB) with a low cutoff; a lone default note
  can look silent.
- Arturia presets and renders are Arturia's content: not committed (renders/
  is ignored; nothing is copied into the repo).

## Juno → Virus calibration (measured 2026-10-26, tools/calibrate_juno.py)

Bare test voices on both synths: filter open, no modulation, gate VCA, effects off.
Tables in calibration.json (`juno_*`, `virus_*` names listed in each step's docstring).

- **Jun-6 V's "brightness / timbre / time / movement" macros do nothing** in the
  Vintage Factory presets (no routings): ignored.
- **Virus Osc Shape between 64 (saw) and 127 (pulse) is an in-phase crossfade**
  of saw and pulse: odd harmonics rise, even ones fall, smoothly. So one Virus
  oscillator plays the Juno's saw+square (same DCO, phase-locked). Fitted Shape
  wanders 80–99 with a flat loss; the translator uses the median (92) and
  interpolates only Pulsewidth. Harmonic shape error 0.5–1.7 dB.
- Juno "50 %" square is really **49.1 % duty** (even harmonics grow with k);
  the PW knob runs duty 0.491 → 0.035 linearly. Juno square is +4.7 dB over its
  saw; Virus pulse only +2.45 dB over its saw. Saw+square on the Juno +8.2 dB.
- **Sub can't use the Virus sub oscillator**: Osc Mainvolume 0 mutes it along
  with the oscillators, and the Juno sub reaches +5.7 dB over the saw. The sub
  plays on osc 2 (pulse 50 %, −12 semitones) mixed by Osc Balance. Noise is not
  muted by Mainvolume 0 (noise-only patches use that).
- **VCF**: the Juno's "Hz" knob is ~1.5× the measured −6 dB corner (knob 1414 →
  933 Hz). Virus analog 4-pole Cutoff 0–127 spans 33 Hz – 16 kHz (−6 dB corner).
  Key tracking: Juno 1.0 = 1.08 (slightly over), Virus 127 = 0.95 (can't quite).
  **Resonance**: Juno peaks reach +25 dB at 1.0 (+12 at 0.8); the Virus tops out
  at +18 dB (127) — Juno res above ~0.9 can't be matched. Juno resonance also
  dips the passband (−2 dB at 0.2), the Virus doesn't.
  Env amount: Juno ~8.7 octaves per 1.0 (linear), Virus 96 = 6.2, 127 = 9.0 oct.
  **Map the envelope by where the sweep peaks, not by its size in octaves.**
  Many Juno presets rest far below the Virus floor (Brass 1's knob 6.7 ≈ 5 Hz;
  Virus Cutoff 0 = 33 Hz), so the same 9-octave sweep overshot by ~3 octaves:
  start loss 17 dB, and the fit stalled at 7 dB with cutoff 0. Below the
  measurable range the Juno's knob → corner ratio (~0.68) is extended.
- **The Virus filter envelope is much slower than its amp envelope** at the same
  value (cutoff rise measured as the level above 2 kHz, 50 % point): attack 32 =
  80 ms (amp: 4 ms), 64 = 365 ms; decay 64 = 155 ms to half-way. Seeding the
  filter env from the amp tables turned Brass 1's 30 ms "blat" into a 0.4 s
  swell. Juno attack 0.03 = 10 ms, 0.1 = 40 ms; decay 1.0 = 120 ms (cutoff
  half-way). Tables `juno_fenv_*` / `virus_fenv_*`. (This probably also
  explains the OB-Xf finding that filter attacks wanted fitting, not the table.)
- **HPF**: Jun-6 V knob up to ~100 is off (corner < 25 Hz); 287 → 111 Hz,
  588 → 249 Hz, 2708 → 1.56 kHz. Virus filter 2 high-pass in **Serial 4 with
  Filter Balance 64 and Filter2 Cutoff Link off** works after the analog filter 1
  (12 dB/oct); Cutoff2 32 → 106 Hz, 48 → 256 Hz, 80 → 1.44 kHz.
- **Envelope**: Juno sustain is linear amplitude (0.5 = −6 dB, 0.1 = −20 dB).
  Juno shown times run long: decay "1.0 s" falls 20 dB in 316 ms, release "1.0 s"
  in 368 ms; attack "0.1 s" rises 10–90 % in 80 ms. Virus decay/release 64 ≈
  600–680 ms to −20 dB, 96 ≈ 2.3–2.7 s. (Measuring a fast decay from the level
  just before the peak reads silence: use the peak itself.)
- **LFO**: Jun-6 V's shown rate is exact (1–20 Hz). Only Virus **LFO 3 has a
  fade-in**, so the Juno LFO (with delay) maps to LFO 3: vibrato on its own
  destination (Osc 1+2 Pitch), VCF and PWM through matrix slots (source "LFO 3
  bipolar"). Juno delay 0.6 s → half depth at 0.5 s; Virus Fade-In 48 → 0.45 s,
  64 → 0.78 s, 96 → 2.8 s. Juno vibrato 0.1 = 5 c, 0.3 = 20 c; Virus LFO 3
  amount 24 = 5 c, 48 = 20 c. Juno VCF LFO 0.1 = ±0.08 oct; matrix LFO 3 →
  cutoff +8 = ±0.1 oct. Many presets leave vibrato at 0.004 (0.7 c): ignored.
  (Pitch tracking through a band-pass: skip its first ~150 ms start-up.)
- **PWM**: LFO mode swings duty one-sided from ~0.49 down (knob 1.0: 0.33–0.49);
  envelope mode goes 0.49 → 0.33 at full envelope. Virus matrix LFO 3 → PW
  amount 63 = ±0.07 around Pulsewidth 64; filter env → PW 63 = 0.35 from PW 0.
  Both just cover the Juno's range.
- **Chorus** (Jun-6 V): modes I and II are stereo (L−R ≈ 0.62 of L+R), I+II is
  mono; the mono sum keeps the modulation. Demos are stereo from now on.
  The Juno's BBD wet path is low-passed: the chorus modulates below ~3 kHz and
  leaves the top steady and 3 dB down. **Virus Classic chorus modulates the whole
  band** (best fit loss 12 vs 1 run to run). **Virus Vintage chorus (type 2)
  behaves like the Juno**: fit loss 1.5. Its mix is "Chorus/Mix2" (Chorus Mix does
  nothing for it), "Chorus/X Over" keeps lows dry. Juno I → Vintage rate 17,
  depth 86; II → rate 38, depth 86 (delay 64, feedback 0, Mix2 127, X Over 0).

## Virus A/B/C compatibility (looked at, then skipped by the user)

- Single format (from source): A/B/C singles are 256 bytes (pages A + B
  only) with one checksum, 267-byte dump. Version byte `preset[0]`:
  0–5 = A (OS 1–3), **6 = B (OS 4)**, **7 = C (OS 6)**, 8 / `0x0C` = TI.
- Gearmulator's C table (`osirusJucePlugin/parameterDescriptions_C.json`)
  has every control our patches use at the same page/index **except unison**:
  TI `0x6F`/120–121 → C page A 97–98. The C table includes Analog 1–4 pole
  filter modes and the EQ; a Virus **B** probably lacks the analog modes
  (inferred, unverified), which all our patches rely on.
- Verifying would need a Virus B/C firmware file for Gearmulator's Osirus.
  User decided (2026-10-24) to skip Virus B.
